  <action>
Write the tests first. They are all writable before the implementation exists:
P_trig(0.5 eV) == 0.5 to 1e-12 for every sharpness on a grid across the declared range;
P_trig(0) == 0.0 exactly; P_trig(1e-6 eV) < 1e-6; P_trig(500 eV) > 1 - 1e-6; strict
monotonicity and range [0, 1] on a dense log grid from 1e-3 to 1e3 eV.

Then implement. Use a logistic in log energy — equivalently the Hill form
P(E) = 1 / (1 + (E50/E)^k) — because its 50% point is at E = E50 identically in k, it
vanishes as E → 0, and it saturates at 1. Reject a logistic in linear energy: it gives
P(0) = 1/(1 + e^{E50/w}) > 0, a nonzero probability of triggering on nothing. Record that
rejection in the module docstring; it is the reason the form was chosen, not a stylistic
preference.

Register both parameters in `params.py` in the same style as `F_PROMPT` / `R_SPOT` /
`F_PROMPT_RANGE`: the 50%-point energy fixed at 0.5 eV, and the sharpness with a stated
default and an explicit scan range. Never write either number as a bare literal inside the
sigmoid. The width is fixed by no project artifact — the module docstring must say so, and
must state that only the 50% point carries a project decision behind it.

Also define the sub-eV regime-boundary constant here (the ~1 eV deposit below which the
trigger curve, not dR/dE_rec, is the reported observable), so that plan 10-05 and later
phases label the boundary from one importable source instead of restating a literal.

Write `10-02-TRIGGER-CURVE-DERIVATION.md` alongside the code: the one-line algebra
P(E50) = 1/(1 + 1^k) = 1/2 showing where the k-independence comes from, the E -> 0+ and
E -> infinity limits, the sign of dP/dE, and the rejected linear-energy logistic with its
P(0) = 1/(1 + e^{E50/w}) evaluated numerically at the width you would otherwise have used.
State plainly that k is fixed by no measurement and that only E50 carries a project decision.

  <action>
There is no single existing efficiency-composition point in the codebase: ε enters inside
`energy_scale.n_qp_yield` as N_qp = ε·E_sensor/Δ_tr, and again as the calibration slope in
`response.py`. So create the composition point rather than assuming one. Write a helper
that takes an already-computed un-triggered quantity (which therefore already contains ε

lives inside the un-triggered quantity and is not replaced.

Then write the two decisive tests.

Factorisation: for a grid of deposit energies, assert `composed(E) == P_trig(E) *
untriggered(E)` exactly, and assert that forcing P_trig ≡ 1 reproduces the pre-existing
chain bit-for-bit. If it does not, the curve modified the chain instead of multiplying it.

composed result changes by exactly the same ratio as the un-triggered result changes, while
P_trig at the same energy is bit-identical. A composed result that is insensitive to ε means
the sigmoid has replaced it — that is the named forbidden proxy, and the test must be
constructed so it would catch it. Say explicitly in the SUMMARY that you checked this test
fails when the composition is rewritten as `composed = P_trig` alone.

Factor Registry, in the same table style as §E and §F: the curve, the 50% point fixed at
0.5 eV, the exposed sharpness and its range, the composition rule stated as an explicit
"this does NOT replace §E's ε ≈ 0.5 and does not modify §F", the phenomenological status,

§F themselves.
  </action>
