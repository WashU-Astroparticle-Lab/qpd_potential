## 1. What the credit column means

A **rejection credit** is a dimensionless multiplicative factor applied to a background *rate*
when that background is re-folded for the wafer.

> **A credit of 1.0 means the background is unchanged — no rejection is taken.**
> 1.0 is the *empty* credit, not full credit. Every row in this document carries 1.0.

That every row carries 1.0 is the result, not a formatting accident. The three tiers differ in
**what does transfer**, which is a separate column:

| Tier | Rejection credit | What transfers |
|---|---|---|
| **L1** | 1.0 | The quantity itself — as an environmental input, or as material attenuation of the incident field re-applied to the wafer's own fold. Never as a credit multiplied onto a rate. |
| **L1\*** | 1.0 | Nothing. |
| **L2** | 1.0 | Nothing (one exception: `row-b08`, where the *background* is inherited and the rejection is not). |

**Credit-basis vocabulary.** The acceptance test for this deliverable requires that *policy* and
*derivation* be distinguished, and they are. Two further basis values are used so that no row is
forced into a credit it does not have:

| Basis | Meaning | Rows |
|---|---|---|
| `policy` | The rejection exists in NUCLEUS's configuration but is not transferable, so this project declines to take it. VALD-09: inherited veto credit defaults to zero unless earned by wafer geometry. | most L1\*/L2 rows, and the two L1 passive-attenuation rows |
| `derivation` | The rejection is *derived* to be identically zero for this payload; no policy default is needed. | `row-b02` only |
| `not-a-rejection-factor` | The statement is not a rejection or attenuation factor at all; it has no credit to give. | the four L1 environmental-input rows and `row-b03` |
| `context` | The statement is a qualifier on another row's factor rather than an independent factor. | `row-b06`, `row-b07` |

## 2. Tier definitions and the swap test

The tiers are generated by one question, applied to each statement:

> **The swap test.** Would this number change if the payload were replaced and *nothing else*
> changed — same site, same cryostat, same shield stack, same vetoes, only a different object at
> the target position?

| Answer | Mechanism | Tier |
|---|---|---|
| **No** | The quantity is a property of the site, the incident field, or bulk material. | **L1** — environmental. Transfers. |
| **Yes**, and the mechanism is an **active detector** operated in anti-coincidence | Rejection is earned by a veto that surrounds and is triggered by the payload. | **L2** — payload-coupled. Credit 1.0. |
| **Yes**, and the mechanism is **passive material** whose *quoted value* is coupled to the payload geometry | The material would attenuate anything, but the published number is measured for a liner in the direct vicinity of a centimetre-scale payload. | **L1\*** — passive but payload-geometry-coupled. Credit 1.0. |

The test is applied by reasoning, not by recomputation. That is recorded as a limitation in §9.

### 2.1 L1\* is an extension of ROADMAP Success Criterion 2, and is labelled as one

ROADMAP Phase 8 Success Criterion 2 specifies a **binary** split, in these words:

> **L1** (environmental — 2.92 ± 0.01 m.w.e. overburden, Table 4 surface fluxes, passive external
> 5 cm Pb + 20 cm borated HDPE attenuation) transfers; **L2** (payload-coupled — COV factor ~5,
> MV+COV > 99.8%, 3×3 multiplicity) defaults to **1.0**.

**This document extends that criterion to three tiers. The extension is presented as an
extension, not as the criterion's original wording.**

The binary split has no slot for the nearly-4π 4 cm boron carbide liner or for the internal
shielding. Both are *passive materials*, which reads L1; but the published suppression factor
attached to the liner is quoted for a nearly-4π geometry in the direct vicinity of a
centimetre-scale payload, which reads L2. Forced into the binary split, they would go to L1 —
because "passive" is the more visible property — and that is exactly the wrong answer:

> **Promoting the B₄C liner and the internal shielding to L1 would flatter the background budget
> at precisely the point where the wafer's size is the disputed quantity.** The wafer's face is
> 45.9× the published 3×3 crystal footprint (crystal basis) or 11.5× a project holder-scale
> estimate (holder basis) — see §5 and `GPD/literature/PITFALLS.md`. A geometry-coupled factor
> transferred wholesale is a credit taken for a geometry we do not have.

L1\* records the disagreement rather than resolving it by fiat. Its credit is 1.0, the same as
L2. The tier exists so that a reader can see *why* a passive material was not transferred, and so
that a future reviewer who disagrees can argue with a named category instead of silently
reclassifying a row.

## 4. The multiplicity row's 1.0 is derived, not defaulted

This is the one row whose credit does not come from the VALD-09 policy default. It comes from a
counting identity established in Plan 08-02 and implemented in `src/qpd_potential/wafer_self_veto.py`.

NUCLEUS's selection (`row-b02`) is a conjunction. Conjunct (ii) is "a hit in one and only one of
the target detectors". Define

```
eps_mult(N) = 1 - P(exactly one of N target channels above threshold)
```

For a single-readout monolithic target, `N = 1`. Any event that triggers at all triggers the one
and only channel, so `P(exactly one) = 1` and `eps_mult(1) = 0` **exactly**. The rejection is
identically zero; the transferable credit is therefore `1 - 0 = 1.0` **by derivation**, and no
policy default is needed or used.

Plan 08-02 established this three ways, all machine-checked:

1. `mult_rejection(1)` returns `0.0` through an early return of the literal, asserted under
   **identity** comparison (`== 0.0`), not a tolerance.
2. The binomial-conditional occupancy model used for `N > 1` **itself** returns 0 at `N = 1` for
   every `p_hit` in (0, 1]: `N p (1-p)^0 / (1 - (1-p)) = p/p = 1`. The identity therefore does not
   depend on the occupancy model at all — the early return agrees with the model rather than
   substituting for it.
3. `mult_rejection(18) > 0` is retained as a unit-test contrast only; no `N = 18` number is
   published, because it spans 0.083 to 0.9999 over `p_hit ∈ [0.01, 0.5]` and is entirely
   model-driven.

**Backing artefact:** `src/qpd_potential/wafer_self_veto.py`; summary at
`GPD/phases/08-veto-envelope-geometry-gate-p-veto/08-02-SUMMARY.md`.
`src/qpd_potential/veto_credit.multiplicity_rejection_is_zero()` re-checks the identity at import
of the caller rather than restating the number, so this row consumes the derivation instead of
asserting it.

**Counterpoint, reported rather than buried** (`row-b07`). NUCLEUS call the marginal benefit of the
IV + single-hit conjunction "very marginal". Read plainly: because the handle they gain from that
cut is small, the **absolute background cost** of the wafer's identically-zero multiplicity handle
is also small. That weakens this project's own "we lose their multiplicity cut" framing. Both
statements stand together: the rejection is exactly zero, **and** its consequence is small.

## 5. Why the B₄C liner and the internal shielding stay in L1\*

Both are passive materials. Neither is an anti-coincidence detector. The argument for L1\* rather
than L1 is entirely about **where the published number was measured**.

`row-b04` states the liner suppresses "the event rates in the CaWO₄ detectors by a factor ∼5".
Three properties of that sentence make the factor geometry-coupled:

1. **It is a nearly-4π liner** (`row-a09`). A 4π geometry's effectiveness is a statement about the
   solid angle subtended at the payload. Change the payload's size and the solid angle changes.
2. **It is quoted in the direct vicinity of a centimetre-scale payload.** The published 3×3 array
   crystal footprint is **2.25 cm²** (mass-closed two independent ways in `08-01-SOURCE-EVIDENCE.md`
   §C.2/§C.3: CaWO₄ array-crystal edge 4.996 mm, Al₂O₃ array-crystal edge 5.008 mm). The wafer's
   face is **103.2256 cm²** — **45.9×** on the crystal basis, **11.5×** on a project holder-scale
   basis. A factor-four spread in the ratio itself, which is why every ratio in this project must
   carry a basis label.
3. **The quoted value is an event-rate reduction in CaWO₄ detectors**, so it embeds a target
   response as well as a geometry. That caveat applies to `row-b10` too, and is why both are
   labelled "material attenuation only" or "nothing" rather than being handed a number.

The same reasoning covers the internal shielding as a whole (`row-a09`): it "follows the same
layer arrangement as the external shielding" *inside* the cryostat, arranged around the target
detectors, and includes a cold muon veto. Its dimensions are set by what it encloses.

**What a reviewer could reasonably say against this**, recorded rather than suppressed: 4 cm of
boron carbide attenuates neutrons whether the object behind it is 2.25 cm² or 103 cm², so the
liner is arguably close enough to pure material attenuation to be L1. That would raise the
transferable credit. The honest response is that the *published value* is geometry-coupled, that
we have no wafer-specific recomputation of it, and that L1\* records the disagreement rather than
deciding it by fiat. If Phase 13 or Phase 16 later recomputes the liner's attenuation for the
wafer's own geometry from first principles, that recomputed number is a derived L1 quantity and
does not require this row to be reclassified.

**What would collapse L1\* into L1:** a source statement showing the ~5× suppression quoted for a
payload-independent configuration. None was found in either the arXiv v1 or the published EPJC
text.

## 6. The baseline configuration: NUCLEUS's shielding without NUCLEUS's vetoes

Phase 16 must report a baseline in which every L1\* and L2 credit is 1.0. **Its name is
"NUCLEUS's shielding without NUCLEUS's vetoes".**

**It is not a conservative subset of NUCLEUS, and this document does not use that word to
describe it.** It is a **different and worse configuration** than either NUCLEUS or an
independently optimised shield, and it must be reported under that description.

The reason is in §5.2.2 of the source. The 5 cm lead thickness was not chosen as a safe minimum;
it was chosen as one leg of a trade-off whose *other* leg is the cryogenic outer veto
(`Q-tradeoff`, newly quoted by this plan, §7):

> "The optimal amount of Pb material in the external and internal gamma shields results from a
> trade-off between (i) the production of secondary particles when exposed to cosmic ray-induced
> neutrons and muons (see section 5.2.1) and (ii) the total reduction of ambient gamma-ray
> backgrounds when combined with the COV."

and the companion statement (`row-b11`):

> "It particularly points out the essential role of the COV in reducing the environmental gamma
> ray contribution down to sufficiently low levels."

Read together: **NUCLEUS's passive gamma shield is deliberately thin because the COV compensates
for it.** More lead would have bought gamma attenuation at the price of more muon- and
neutron-induced secondaries, and they accepted the thin shield precisely because an active
germanium veto sits inside it. Evidence-block **§A.11** (§2 of the source, with its own recorded
command there) records the COV as one that "hermetically covers the cryogenic target detectors,
with the primary purpose of complementing the relatively modest attenuation of the NUCLEUS passive
shielding to external gamma rays" — the paper's own words for the same design logic.

Therefore:

- Keeping their 5 cm lead while dropping their vetoes is **not** NUCLEUS. It is NUCLEUS with one
  leg of a two-leg trade-off removed.
- It is also **not** an independently optimised unvetoed shield. Nobody designing a passive-only
  110 g germanium experiment would choose 5 cm of lead; without a COV to catch the secondaries,
  the optimum thickness is a different number entirely.
- It is worse than both. Calling it a safe lower bound on NUCLEUS's configuration would
  misrepresent a known-suboptimal configuration as a bound, and a referee — plausibly a NUCLEUS
  author — will find this immediately.

**How Phase 16 must report it.** As "NUCLEUS's shielding without NUCLEUS's vetoes", stated to be
a different and worse configuration than either alternative, with the trade-off sentence above
quoted or cited. The S/B computed under it is a valid arithmetic lower bound on S/B *at fixed
shield*, and that is the only sense in which it bounds anything; it is not a bound on what an
optimised independent design would achieve.

## 8. Where the credits live in code

A credit recorded only in this table would eventually be typed into a formula by someone. It is
therefore also in code:

| Object | Value | File |
|---|---|---|
| `L2_CREDIT` | `1.0` exactly | `src/qpd_potential/veto_credit.py` |
| `L1STAR_CREDIT` | `1.0` exactly | `src/qpd_potential/veto_credit.py` |

| `TAXONOMY` | one entry per row id in §3 | `src/qpd_potential/veto_credit.py` |
| `credit_for(row_id)` | returns `1.0`, raises on an unknown id | `src/qpd_potential/veto_credit.py` |

Any downstream code path that wants a rejection factor must **name the statement** and receives
1.0. Changing any of these constants away from 1.0 requires a wafer-specific veto geometry and a
documented argument, and will appear as a reviewable diff.

`tests/test_veto_credit.py` additionally walks every module under `src/qpd_potential/` with two
decidable rules: a literal denylist on `99.8` / `0.998` as evaluated numbers, and a naming rule
requiring every module-level numeric constant whose name contains `CREDIT`, `REJECTION` or
`VETO_FACTOR` to equal exactly 1.0. Both rules are demonstrated to fire on injected violations
and to stay silent on Plan 08-03's geometry constants.

**What the guard does not catch, stated so it is not mistaken for completeness.**
An anonymous inline literal — `rate / 5` inside a function body — is invisible to both rules,
because no decidable rule can separate it from a legitimate arithmetic constant. A rule that tried
would false-positive on `COV_CRYSTAL_THICKNESS_CM = 2.5`, `B4C_THICKNESS_CM = 4.0` and the wafer's
`LZ = 0.20`, and a guard that false-positives gets disabled — the same failure as having none. The
guard raises the cost of reintroducing a veto credit and makes the reviewable-diff path the path
of least resistance; it is not a proof that no rejection factor can enter.
